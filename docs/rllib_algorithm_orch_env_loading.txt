  ---
  The three Ray actor types

  1. SAC — Algorithm driver / coordinator

  This is the orchestration process. It runs the training loop: it tells
  EnvRunners to collect episodes, manages the replay buffer, decides when to
  trigger learning, and runs evaluation (since
  evaluation_parallel_to_training=False, evaluation episodes run here, in this
  same process). It does not do gradient updates and does not run environments
  for training.

  It is the "boss" — delegates work but doesn't do the heavy lifting
   itself.

  2. SingleAgentEnvRunner pid=2570588/2570589 — Environment samplers

  These 2 processes exist because num_env_runners=2. Their only job is to run 
  the environment and collect trajectories. They hold an env instance, query the
   policy (inference), step the env, and ship episodes back to the algorithm
  driver. They use CPU only.

  3. _WrappedExecutable pid=2570798 — Learner (GPU worker)

  This is the gradient computation process. It takes batches of experience from
  the replay buffer and performs the actual SGD updates on the neural network
  weights. This is what uses the GPU. It never touches the environment.

  ---
  Why the separation?

  EnvRunners (CPU)          Algorithm Driver (CPU)       Learner (GPU)
  ──────────────────         ─────────────────────        ──────────────
  run env → episodes  ──→   buffer + orchestration  ──→  gradient updates
                      ←──   updated weights          ←──

  The key insight is that sampling and learning have different resource 
  requirements:
  - Sampling is CPU-bound (env physics, Python logic)
  - Learning is GPU-bound (matrix ops on the network)

  Decoupling them means the GPU is never idle waiting for env steps, and env
  runners don't block on gradient computation.

  ---
  So in your run: 4 distinct processes

  ┌────────────┬───────┬──────────────────────────────┐
  │  Process   │ Count │             Role             │
  ├────────────┼───────┼──────────────────────────────┤
  │ SAC driver │ 1     │ Orchestration + evaluation   │
  ├────────────┼───────┼──────────────────────────────┤
  │ EnvRunners │ 2     │ Sampling (training episodes) │
  ├────────────┼───────┼──────────────────────────────┤
  │ Learner    │ 1     │ Gradient updates (GPU)       │
  └────────────┴───────┴──────────────────────────────┘

  The SAC label on the driver process refers to the algorithm object, not to
  "the thing doing SAC gradient updates" — that's the Learner. The naming can be
   confusing precisely because in older RLlib, one process did both.
