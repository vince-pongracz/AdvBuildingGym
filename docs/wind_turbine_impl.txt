     Wind Turbine Infrastructure

     Context

     The environment already has wind speed data (avg_wind_speed_norm in [0, 1])
      provided by WeatherDataSource. Currently nothing consumes it for power
     generation. Adding a wind turbine gives the agent another generation source
      to manage, complementing the existing solar panel. Unlike the solar panel
     (fully passive), the wind turbine has a policy-controlled curtailment
     action so the agent can regulate how much wind power is actually utilised.

     Design

     Pattern: Follows SolarPanel closely but adds a 1D continuous action for
     curtailment.

     - Action: wind_curtailment in [0, 1] — 0 = fully curtailed (no power), 1 =
     full utilisation
     - State: No new state key needed — avg_wind_speed_norm already exists from
     WeatherDataSource
     - Power output: available_power × curtailment_action, where available power
      comes from a realistic cubic power curve
     - Sign convention: negative = production (same as solar panel)
     - Rated capacity: 5 kW peak
     - Penalisable consumption: 0 (generation source, exempt)

     Power curve (cubic with cut-in/cut-out)

     The standard wind power equation is P = ½ρAv³, meaning power scales with
     the cube of wind speed.
     Real turbines operate in three regimes defined by cut-in, rated, and
     cut-out speeds.
     - Link: https://en.wikipedia.org/wiki/Wind_turbine_design#Power_curve
     - Link:
     https://www.sciencedirect.com/topics/engineering/wind-turbine-power-curve

     Raw wind speed is recovered from the normalised value using the data max
     (~23 m/s). The power curve:
     - Below cut-in (3 m/s): 0 power — typical small turbine cut-in speed
       - Link: https://en.wikipedia.org/wiki/Cut-in_speed
     - Between cut-in and rated speed (12 m/s): power ∝ (v − v_cut_in)³ /
     (v_rated − v_cut_in)³
       - Cubic relationship from Betz's law (P ∝ v³)
       - Link: https://en.wikipedia.org/wiki/Betz%27s_law
     - Between rated and cut-out (25 m/s): full rated power — generator limit
     - Above cut-out (25 m/s): 0 power — safety shutdown to prevent structural
     damage
       - Link: https://en.wikipedia.org/wiki/Cut-out_speed

     Default parameter values (typical for small residential 5 kW turbines):
     - cut_in_speed = 3.0 m/s — common for small wind turbines (2.5–4 m/s range)
     - rated_speed = 12.0 m/s — typical rated wind speed for small turbines
     (10–14 m/s)
     - cut_out_speed = 25.0 m/s — IEC 61400-2 standard for small wind turbines
       - Link: https://webstore.iec.ch/en/publication/5433
     - rated_power_kW = 5.0 kW — matched to solar panel capacity for balanced
     generation mix
     - wind_speed_max = 25.0 m/s — normalisation ceiling; our DWD data max is
     ~23 m/s

     Since we only have avg_wind_speed_norm (normalised to [0, 1] by data max),
     we need the raw max wind speed. The weather source exposes _temp_abs_max in
      info but not a wind equivalent. Two options:
     1. Store wind_speed_max as a constructor parameter on the turbine (default
     25.0 m/s — covers the data range of 0–23 m/s)
     2. Read it from info

     Choice: Constructor parameter — simple, explicit, no coupling to weather
     source internals.

     Files to modify

     1. New file: adv_building_gym/devices/infrastructure/wind_turbine.py

     WindTurbine class:
     - __init__(name, max_power_kW, rated_power_kW, cut_in_speed, rated_speed, 
     cut_out_speed, wind_speed_max)
       - Defaults: rated_power_kW=5.0, cut_in_speed=3.0, rated_speed=12.0,
     cut_out_speed=25.0, wind_speed_max=25.0
     - max_consumption_kW → 0.0 (generation only)
     - max_export_kW → max_power_kW
     - setup_spaces: adds wind_curtailment action in Box([0, 1], shape=(1,))
     - exec_action: reads avg_wind_speed_norm from states, denormalises, applies
      power curve, multiplies by curtailment action, writes wind_action into
     actions
     - update_state: no extra state to write (wind speed already in obs)
     - get_electric_consumption: returns -current_production_kW
     - get_penalisable_consumption: returns 0.0
     - Register with ComponentRegistry

     2. adv_building_gym/devices/infrastructure/__init__.py

     Add from .wind_turbine import WindTurbine and add to __all__.

     3. adv_building_gym/config/env_config.py

     - Import WindTurbine
     - Add to create_infras(): WindTurbine("wind_turbine", max_power_kW=5.0, 
     rated_power_kW=5.0)

     1. Run a short training: python run_train_ray.py --algorithm sac --episodes
      10 — confirm no shape mismatches or errors
     2. Check that wind_curtailment appears in the action space and wind_action
     is written during steps
