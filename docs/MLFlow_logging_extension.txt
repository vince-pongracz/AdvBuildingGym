● That's just how TensorBoard works — the runs sidebar is always a flat list of
  relative paths from --logdir. There's no collapsible tree view built in.

  Your options to filter/group:

  1. Regex filter (easiest) — In the TensorBoard sidebar, there's a text box
  above the run list. Type 20260404_172532 and it filters to only that run's
  iterations.
  2. Point --logdir at a specific run — Instead of the parent:
  tensorboard --logdir ep_metrics/eval_trajectories/20260404_172532
  2. Then only that run's iter_* entries appear.
  3. --logdir_spec — Give each run a named group:
  tensorboard --logdir_spec run1:ep_metrics/eval_trajectories/20260404_172532,ru
  n2:ep_metrics/eval_trajectories/20260404_175807

  Option 1 (regex filter) is probably what you want — no code changes, just type
   the date prefix in the filter box and it scopes the sidebar to that run.

❯ I think collapsible grouping is the target                                    

● TensorBoard doesn't have native collapsible run grouping. The sidebar is
  always a flat list.

  The closest alternatives that give a tree-like experience:

  1. MLflow — has a native collapsible experiment/run hierarchy, integrates with
   TensorBoard event files. You can point it at existing tfevents dirs.
  2. Weights & Biases (wandb) — groups runs by configurable fields, collapsible
  in the UI.
  3. TensorBoard.dev — no collapsible grouping either.
  4. Custom TensorBoard plugin — possible but significant effort for a sidebar
  UI change.

  Would you like to integrate one of these (MLflow is the lightest lift since it
   reads tfevents natively), or is the regex filter in TensorBoard good enough
  for now?

❯ How would you do the regex filter and how the MLFlow solution:                

● Option 1: TensorBoard Regex Filter

  No code changes needed. In TensorBoard's left sidebar, there's a text input
  field at the top of the runs list. It accepts regex:

  - 20260404_172532 — show only that run's iterations
  - 20260404 — show all runs from that day
  - iter_000004 — show iter 4 across all runs
  - 20260404_172532/iter_00000[48] — show specific iterations from one run

  That's it — just type and the list filters live.

  ---
  Option 2: MLflow with Collapsible Grouping

  MLflow can read your existing tfevents files and display them in a collapsible
   experiment/run/nested-run hierarchy.

  The structure would look like:

  MLflow UI sidebar:
  ▼ eval_trajectories          (Experiment)
    ▼ 20260404_172532          (Parent Run)
        iter_000004            (Child Run)
        iter_000008            (Child Run)
    ▼ 20260404_175807          (Parent Run)
        iter_000004            (Child Run)
        iter_000008            (Child Run)

  This requires:

  1. Install: pip install mlflow
  2. A small import script that walks your existing eval_trajectories/
  directory, creates an MLflow experiment, and logs each exec_date as a parent
  run with its iter_* entries as nested child runs — reading the scalar data
  from the tfevents files.
  3. Modify the callback to log to MLflow directly instead of (or alongside)
  TensorBoard, so future runs get the hierarchy automatically.
